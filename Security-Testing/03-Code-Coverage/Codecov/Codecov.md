# Codecov

## Introduction

Codecov is a leading code coverage reporting and analysis tool that helps development teams understand which parts of their codebase are tested and which are not. By integrating seamlessly with CI/CD pipelines and version control systems, Codecov provides actionable insights into test coverage, identifies uncovered code, and tracks coverage trends over time. It supports over 20 programming languages and integrates with all major CI/CD platforms.

### What is Codecov?

Codecov processes code coverage reports generated by various testing frameworks and presents the data in an easy-to-understand format through:
- **Visual coverage reports**: Line-by-line coverage visualization
- **Pull request comments**: Automated coverage reports on PRs
- **Coverage badges**: Display coverage percentage on README
- **Trend analysis**: Track coverage changes over time
- **Branch comparison**: Compare coverage across branches
- **Coverage goals**: Set and enforce coverage targets

## Key Features

### Coverage Visualization
- **Line coverage**: Which lines are executed
- **Branch coverage**: Which conditional branches are tested
- **File tree view**: Navigate coverage by file structure
- **Diff coverage**: See coverage of changed lines only
- **Sunburst charts**: Visual representation of coverage distribution
- **Coverage heatmaps**: Identify hotspots and cold spots

### Pull Request Integration
- **Inline comments**: Coverage feedback directly on PRs
- **Status checks**: Pass/fail based on coverage thresholds
- **Coverage diff**: Show how PR affects overall coverage
- **Automated suggestions**: Identify untested code in PRs
- **Base comparison**: Compare against target branch

### Reporting and Analytics
- **Dashboard**: Overview of all projects
- **Trends**: Historical coverage data
- **Flags**: Track coverage for different test suites
- **Components**: Group files for separate tracking
- **Annotations**: Custom metadata for analysis

### Quality Gates
- **Project coverage**: Minimum coverage percentage
- **Patch coverage**: Coverage of new/changed code
- **Coverage change**: Allowed decrease in coverage
- **File coverage**: Per-file coverage requirements
- **Conditional checks**: Advanced rule configuration

## Installation and Setup

### Step 1: Sign Up

```yaml
Method 1: GitHub Integration
  1. Visit: https://about.codecov.io/
  2. Click "Sign up with GitHub"
  3. Authorize Codecov
  4. Select repositories to enable

Method 2: GitLab Integration
  1. Visit: https://about.codecov.io/
  2. Click "Sign up with GitLab"
  3. Authorize Codecov
  4. Select projects to enable

Method 3: Bitbucket Integration
  1. Visit: https://about.codecov.io/
  2. Click "Sign up with Bitbucket"
  3. Authorize Codecov
  4. Select repositories to enable
```

### Step 2: Get Repository Upload Token

```bash
# Method 1: From Codecov Dashboard
# 1. Select your repository
# 2. Settings → General
# 3. Copy the "Repository Upload Token"

# Method 2: From CLI (if already configured)
curl -X GET "https://codecov.io/api/v2/gh/<username>/<repo>/settings" \
  -H "Authorization: token <CODECOV_TOKEN>"

# Store token as environment variable or CI/CD secret
# GitHub: Settings → Secrets → New repository secret
# GitLab: Settings → CI/CD → Variables
# CircleCI: Project Settings → Environment Variables
```

### Step 3: Install Codecov Uploader

```bash
# Linux/macOS - Official Uploader (Recommended)
curl -Os https://uploader.codecov.io/latest/linux/codecov
chmod +x codecov
sudo mv codecov /usr/local/bin/

# Windows (PowerShell)
Invoke-WebRequest -Uri https://uploader.codecov.io/latest/windows/codecov.exe -OutFile codecov.exe

# macOS via Homebrew
brew install codecov

# npm global installation (deprecated but still works)
npm install -g codecov

# Verify installation
codecov --version
```

### Step 4: Configure Your Project

**codecov.yml Configuration:**

```yaml
# .codecov.yml or codecov.yml in repository root

# Coverage targets
coverage:
  precision: 2  # Number of decimal places
  round: down   # Round down or up
  range: 70..100  # Green if >100%, yellow if 70-100%, red if <70%
  
  status:
    project:
      default:
        target: 80%  # Minimum coverage for entire project
        threshold: 2%  # Allow 2% decrease
        if_ci_failed: error  # Report status if CI fails
    
    patch:
      default:
        target: 90%  # New code must have 90% coverage
        if_not_found: success
        if_ci_failed: error

# Ignore certain paths
ignore:
  - "tests/**/*"
  - "**/*.test.js"
  - "**/__tests__/**"
  - "docs/**/*"
  - "*.md"

# Comment configuration for pull requests
comment:
  layout: "reach, diff, flags, files"
  behavior: default  # Update same comment or create new
  require_changes: false  # Always comment, even if no change
  require_base: no
  require_head: yes

# Define coverage flags for different test suites
flags:
  unit:
    paths:
      - src/
  integration:
    paths:
      - tests/integration/
  e2e:
    paths:
      - tests/e2e/

# Component-based coverage
component_management:
  individual_components:
    - component_id: backend
      name: Backend
      paths:
        - src/backend/**
    - component_id: frontend
      name: Frontend
      paths:
        - src/frontend/**
```

## Generating Coverage Reports

### JavaScript/TypeScript (Jest)

```json
// package.json
{
  "scripts": {
    "test": "jest --coverage"
  },
  "jest": {
    "collectCoverage": true,
    "coverageDirectory": "coverage",
    "coverageReporters": ["json", "lcov", "text", "clover"],
    "collectCoverageFrom": [
      "src/**/*.{js,jsx,ts,tsx}",
      "!src/**/*.test.{js,jsx,ts,tsx}",
      "!src/**/__tests__/**"
    ]
  }
}
```

```bash
# Run tests with coverage
npm test

# Upload to Codecov
codecov
```

### Python (pytest with coverage.py)

```bash
# Install coverage dependencies
pip install pytest pytest-cov

# Run tests with coverage
pytest --cov=src --cov-report=xml --cov-report=html

# Upload to Codecov
codecov -f coverage.xml
```

**pytest.ini:**
```ini
[pytest]
addopts = --cov=src --cov-report=xml --cov-report=html --cov-report=term
```

### Java (JaCoCo with Maven)

```xml
<!-- pom.xml -->
<build>
  <plugins>
    <plugin>
      <groupId>org.jacoco</groupId>
      <artifactId>jacoco-maven-plugin</artifactId>
      <version>0.8.11</version>
      <executions>
        <execution>
          <goals>
            <goal>prepare-agent</goal>
          </goals>
        </execution>
        <execution>
          <id>report</id>
          <phase>test</phase>
          <goals>
            <goal>report</goal>
          </goals>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
```

```bash
# Run tests and generate coverage
mvn clean test jacoco:report

# Upload to Codecov
codecov -f target/site/jacoco/jacoco.xml
```

### Go

```bash
# Run tests with coverage
go test -v -coverprofile=coverage.out ./...

# Generate coverage report
go tool cover -html=coverage.out -o coverage.html

# Upload to Codecov
codecov -f coverage.out
```

### C#/.NET (Coverlet)

```bash
# Install Coverlet
dotnet add package coverlet.msbuild

# Run tests with coverage
dotnet test /p:CollectCoverage=true /p:CoverletOutputFormat=opencover

# Upload to Codecov

```

```ruby

  add_filter '/test/'
  add_filter '/spec/'
end
```


## CI/CD Integration

### GitHub Actions

```yaml
name: CI with Code Coverage

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Full history for better analysis
      
      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Run tests with coverage
        run: npm test -- --coverage
      
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v4
        with:
          token: ${{ secrets.CODECOV_TOKEN }}
          files: ./coverage/lcov.info
          flags: unittests
          name: codecov-umbrella
          fail_ci_if_error: true
          verbose: true
      
      # Alternative: Upload multiple coverage files
      - name: Upload coverage (alternative)
        uses: codecov/codecov-action@v4
        with:
          token: ${{ secrets.CODECOV_TOKEN }}
          directory: ./coverage
          flags: unittests
          name: codecov-umbrella
```

### GitLab CI

## Advanced Features

### Coverage Flags

Flags allow you to track coverage for different test suites separately:

```yaml
# .codecov.yml
flags:
  unit:
    paths:
      - src/
    carryforward: true  # Use previous upload if missing
  
  integration:
    paths:
      - tests/integration/
  
  e2e:
    paths:
      - tests/e2e/

# Upload with flags
codecov -f coverage-unit.xml -F unit
codecov -f coverage-integration.xml -F integration
codecov -f coverage-e2e.xml -F e2e
```

### Components

Group files into logical components for separate tracking:

```yaml
# .codecov.yml
component_management:
  individual_components:
    - component_id: api
      name: API Layer
      paths:
        - src/api/**
      
    - component_id: database
      name: Database Layer
      paths:
        - src/db/**
      
    - component_id: frontend
      name: Frontend
      paths:
        - src/components/**
        - src/pages/**
```

### Annotations

Add custom metadata to coverage uploads:

```bash
# Upload with custom annotations
codecov \
  -f coverage.xml \
  -e COMMIT_SHA,BUILD_NUMBER \
  -B $BRANCH_NAME \
  -C $COMMIT_SHA \
  -b $BUILD_NUMBER
```

### Carryforward Flags

Preserve coverage from previous uploads when certain tests don't run:

```yaml
# .codecov.yml
flags:
  integration:
    carryforward: true
    carryforward_mode: all
```

```bash
# Upload with carryforward
codecov -f coverage.xml -F unit --carryforward-flags integration
```

## Best Practices

### 1. Set Realistic Coverage Targets

```yaml
Coverage Goals by Project Type:
  
  Critical Systems (Banking, Healthcare):
    - Target: 90%+
    - Patch: 95%+
    - Focus: 100% for critical paths
  
  Business Applications:
    - Target: 80%
    - Patch: 85%
    - Focus: Core business logic
  
  Web Applications:
    - Target: 70%
    - Patch: 75%
    - Focus: API and business logic (not UI components)
  
  Libraries/SDKs:
    - Target: 85%
    - Patch: 90%
    - Focus: All public APIs
  
  Experimental/Prototypes:
    - Target: 60%
    - Patch: 60%
    - Focus: Main features only
```

### 2. Focus on Quality, Not Just Quantity

```yaml
Meaningful Coverage:
  ✓ Test business logic thoroughly
  ✓ Test error handling paths
  ✓ Test edge cases
  ✓ Test integration points
  
  ✗ Don't chase 100% coverage
  ✗ Don't test trivial code (getters/setters)
  ✗ Don't sacrifice test quality for coverage
  ✗ Don't test framework code
```

### 3. Use Differential Coverage

```yaml
# .codecov.yml
coverage:
  status:
    patch:
      default:
        target: 90%  # New code must have high coverage
        threshold: 0%  # No decrease allowed
    
    project:
      default:
        target: 80%  # Overall can be lower
        threshold: 2%  # Allow small decrease
```

### 4. Exclude Irrelevant Files

```yaml
# .codecov.yml
ignore:
  - "**/*.test.js"
  - "**/__tests__/**"
  - "**/__mocks__/**"
  - "**/node_modules/**"
  - "**/vendor/**"
  - "**/dist/**"
  - "**/build/**"
  - "**/*.config.js"
  - "**/*.min.js"
  - "**/migrations/**"
  - "**/*generated*"
```

### 5. Monitor Coverage Trends

```yaml
Regular Reviews:
  Daily:
    - Check PR coverage comments
    - Ensure new code is tested
  
  Weekly:
    - Review coverage trends
    - Identify decreasing coverage
    - Prioritize untested areas
  
  Monthly:
    - Deep dive on low coverage files
    - Update coverage targets
    - Team coverage retrospective
  
  Quarterly:
    - Review overall strategy
    - Adjust thresholds
    - Celebrate improvements
```

### 6. Integrate with Code Review

```yaml
PR Workflow:
  1. Developer creates PR
  2. CI runs tests with coverage
  3. Codecov comments on PR with:
     - Coverage diff
     - Uncovered lines
     - Coverage decrease
  4. Reviewers check:
     - Are new features tested?
     - Coverage meets threshold?
     - Tests are meaningful?
  5. Merge only if coverage passes
```

## Troubleshooting

### Common Issues

**1. Coverage not appearing:**
```bash
# Check:
- Upload token is correct
- Coverage file format is supported
- File paths are correct
- Network connectivity to Codecov
- CI logs for upload errors

# Debug upload:
codecov -f coverage.xml -v  # Verbose mode
```

**2. Wrong coverage percentage:**
```bash
# Possible causes:
- Multiple uploads overwriting each other
- Incorrect file paths in coverage report
- Wrong source root directory
- Ignored files not properly configured

# Solution:
codecov -f coverage.xml -R /path/to/source/root
```

**3. PR comments not appearing:**
```bash
# Verify:
1. GitHub App is installed and authorized
2. Codecov has PR comment permissions
3. codecov.yml comment settings are correct
4. PR is from same repository (not fork)

# Check settings in:
Repository Settings → Integrations → Codecov
```

**4. Status checks failing unexpectedly:**
```bash
# Review:
- Coverage thresholds in codecov.yml
- Base branch coverage (comparison target)
- Carryforward settings
- Flag-specific status checks

# Temporarily disable:
# .codecov.yml
coverage:
  status:
    project:
      default:
        informational: true  # Don't fail CI
```

## Real-World Use Cases

### Use Case 1: Open Source Project Quality

**Scenario**: Popular npm package wants to maintain high code quality and attract contributors.

**Implementation**:
```yaml
Coverage Strategy:
  - Target: 85% overall
  - Patch: 90% for new code
  - Badge on README

  1. Contributor submits PR
  2. CI runs tests with coverage
  3. Codecov comments with results

Benefits:
  - Visible quality indicator

  - Consistent test standards
```

**Implementation**:

```yaml
Organization Setup:
  - Centralized Codecov account
  - Shared codecov.yml template
  - Team-specific flags
  - Service-specific components

Standards:
  - Minimum 80% coverage
  - New services must start at 85%

  - Monthly coverage reviews

Monitoring:
  - Team dashboards
  - Coverage trends
  - Slack notifications
  - Executive reports

Results:
  - Consistent quality across services
  - Easy to identify risky services
  - Better testing culture
  - Reduced production bugs
```

### Use Case 3: Monorepo with Multiple Apps

**Scenario**: Monorepo contains frontend, backend, mobile apps, and shared libraries.

**Implementation**:
```yaml
# .codecov.yml
component_management:
  individual_components:
    - component_id: frontend
      name: Frontend App
      paths:
        - packages/frontend/**
      
    - component_id: backend
      name: Backend API
      paths:
        - packages/backend/**
      
    - component_id: mobile
      name: Mobile App
      paths:
        - packages/mobile/**
      
    - component_id: shared
      name: Shared Libraries
      paths:
        - packages/shared/**

  frontend-unit:
    paths:
      - packages/frontend/src/**
  backend-unit:
    paths:
      - packages/backend/src/**

CI Strategy:
  - Parallel test runs for each package
  - Separate coverage uploads with flags
  - Component-specific status checks
  - Combined overall coverage

Benefits:
  - Independent coverage tracking
  - Team ownership clarity
  - Targeted improvements
  - Prevent cross-contamination
```
