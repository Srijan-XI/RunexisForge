# Milvus

## Introduction

Milvus is an open-source vector database built for scalable similarity search and AI applications. It provides high-performance vector search capabilities for unstructured data and is designed to handle billions of vectors efficiently.

### What is Milvus?

Milvus is a cloud-native vector database that stores, indexes, and manages massive embedding vectors generated by deep learning models and other machine learning algorithms. It's designed specifically for similarity search on large-scale vector data.

### Key Features

- **Open Source**: Apache 2.0 licensed, fully open source
- **High Performance**: Billion-scale vector search in milliseconds
- **Hybrid Search**: Combine vector and scalar filtering
- **Multiple Index Types**: HNSW, IVF, FLAT, DiskANN, and more
- **Cloud-Native**: Kubernetes-ready, scalable architecture
- **Multi-tenancy**: Support for multiple isolated collections
- **Rich SDKs**: Python, Java, Go, Node.js, and RESTful API
- **GPU Acceleration**: Support for GPU-accelerated indexing and search
- **Time Travel**: Query historical data with MVCC
- **Scalar Filtering**: Advanced filtering on metadata fields

### Use Cases

- **Semantic Search**: Search documents, images, videos by meaning
- **Recommendation Systems**: Product, content, and user recommendations
- **Question Answering**: Build intelligent Q&A and RAG systems
- **Image/Video Retrieval**: Find similar multimedia content
- **Anomaly Detection**: Identify outliers in vector space
- **Drug Discovery**: Molecular similarity search
- **DNA Sequence Analysis**: Genetic similarity matching
- **Face Recognition**: Identity verification and matching

### Milvus vs Other Vector Databases

| Feature | Milvus | Pinecone | Weaviate | Qdrant |
|---------|--------|----------|----------|--------|
| **Deployment** | Self-hosted/Cloud | Managed | Self-hosted/Cloud | Self-hosted/Cloud |
| **License** | Apache 2.0 | Proprietary | BSD-3 | Apache 2.0 |
| **Scale** | Billions+ | Billions+ | Millions | Millions |
| **GPU Support** | Yes | No | No | Limited |
| **Cost** | Free (self-hosted) | Pay-per-use | Free (self-hosted) | Free (self-hosted) |
| **Index Types** | 10+ | Limited | Limited | Limited |

### Architecture Overview

**Milvus Components:**

**Standalone Mode** (Single instance):
- All components in one process
- Good for development and small deployments

**Cluster Mode** (Distributed):
- **Coordinator Services**:
  - Root Coordinator: DDL operations, metadata
  - Data Coordinator: Data segment management
  - Query Coordinator: Query task management
  - Index Coordinator: Index building
- **Worker Nodes**:
  - Query Node: Vector search execution
  - Data Node: Data persistence
  - Index Node: Index building
- **Storage**:
  - Object Storage (S3/MinIO): Log and data files
  - Meta Store (etcd): Metadata storage
  - Message Queue (Pulsar/Kafka): Message streaming

## Installation & Setup

### Prerequisites

- Operating System: Linux, macOS, or Windows (WSL)
- Docker and Docker Compose (recommended)
- Minimum RAM: 8GB (16GB+ for production)
- Python 3.7+ (for client)
- Kubernetes (for cluster deployment)

### Installation Methods

#### Method 1: Docker Compose (Recommended for Getting Started)

**Standalone Milvus:**

```bash
# Download docker-compose configuration
wget https://github.com/milvus-io/milvus/releases/download/v2.3.3/milvus-standalone-docker-compose.yml -O docker-compose.yml

# Start Milvus
docker-compose up -d

# Check status
docker-compose ps
```

**docker-compose.yml:**
```yaml
version: '3.5'

services:
  etcd:
    image: quay.io/coreos/etcd:v3.5.5
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision
      - ETCD_AUTO_COMPACTION_RETENTION=1000
      - ETCD_QUOTA_BACKEND_BYTES=4294967296
      - ETCD_SNAPSHOT_COUNT=50000
    volumes:
      - etcd:/etcd
    command: etcd -advertise-client-urls=http://127.0.0.1:2379 -listen-client-urls http://0.0.0.0:2379 --data-dir /etcd

  minio:
    image: minio/minio:RELEASE.2023-03-20T20-16-18Z
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    volumes:
      - minio:/minio_data
    command: minio server /minio_data --console-address ":9001"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3

  standalone:
    image: milvusdb/milvus:v2.3.3
    command: ["milvus", "run", "standalone"]
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    volumes:
      - milvus:/var/lib/milvus
    ports:
      - "19530:19530"
      - "9091:9091"
    depends_on:
      - etcd
      - minio

volumes:
  etcd:
  minio:
  milvus:
```

```bash

helm install milvus milvus/milvus -f values.yaml
```

#### 2. Create a Collection

**Python:**
```python
from pymilvus import Collection, FieldSchema, CollectionSchema, DataType

# Define schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=False),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=128),
    FieldSchema(name="title", dtype=DataType.VARCHAR, max_length=200),
    FieldSchema(name="year", dtype=DataType.INT32),
    FieldSchema(name="category", dtype=DataType.VARCHAR, max_length=100)
]

schema = CollectionSchema(
    fields=fields,
    description="Article collection"
)

# Create collection
collection = Collection(
    name="articles",
    schema=schema
)
```

**With Auto ID:**
```python
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=768),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=65535)
]

schema = CollectionSchema(fields=fields)
collection = Collection("documents", schema=schema)
```

#### 3. Create Index

**Python:**
```python
# Create HNSW index for vector search
index_params = {
    "metric_type": "L2",
    "index_type": "HNSW",
    "params": {"M": 8, "efConstruction": 64}
}

collection.create_index(
    field_name="embedding",
    index_params=index_params
)

# Create index on scalar field
collection.create_index(
    field_name="category",
    index_name="category_index"
)

# Wait for index to complete
collection.load()
```

**Index Types:**
- **FLAT**: Brute-force, 100% recall, slow for large datasets
- **IVF_FLAT**: Inverted file, good balance
- **IVF_SQ8**: Scalar quantization, less memory
- **IVF_PQ**: Product quantization, even less memory
- **HNSW**: Graph-based, fast, high recall
- **DiskANN**: Disk-based for very large datasets

#### 4. Insert Data

**Python - Insert Vectors:**
```python
import random

# Prepare data
num_entities = 1000
entities = [
    [i for i in range(num_entities)],  # IDs
    [[random.random() for _ in range(128)] for _ in range(num_entities)],  # Vectors
    [f"Article {i}" for i in range(num_entities)],  # Titles
    [random.randint(2000, 2024) for _ in range(num_entities)],  # Years
    [random.choice(["tech", "science", "sports"]) for _ in range(num_entities)]  # Categories
]

# Insert
insert_result = collection.insert(entities)
print(f"Inserted {len(insert_result.primary_keys)} entities")

# Flush to ensure data is written
collection.flush()
```

**Python - Batch Insert:**
```python
batch_size = 1000
for i in range(0, total_records, batch_size):
    batch_data = prepare_batch(i, batch_size)
    collection.insert(batch_data)
    collection.flush()
```

#### 5. Search Vectors

**Python - Basic Search:**
```python
# Define search parameters
search_params = {
    "metric_type": "L2",
    "params": {"ef": 64}
}

# Search
results = collection.search(
    data=[[random.random() for _ in range(128)]],  # Query vector
    anns_field="embedding",
    param=search_params,
    limit=10,
    output_fields=["title", "year", "category"]
)

# Process results
for hits in results:
    for hit in hits:
        print(f"ID: {hit.id}, Distance: {hit.distance}")
        print(f"Title: {hit.entity.get('title')}")
```

**Python - Search with Filter:**
```python
# Search with scalar filtering
results = collection.search(
    data=[query_vector],
    anns_field="embedding",
    param=search_params,
    limit=10,
    expr="year > 2020 and category == 'tech'",
    output_fields=["title", "year"]
)
```

**Python - Hybrid Search:**
```python
# Search with complex expression
results = collection.search(
    data=[query_vector],
    anns_field="embedding",
    param=search_params,
    limit=10,
    expr="year in [2020, 2021, 2022] and category != 'sports'",
    output_fields=["*"]  # Return all fields
)
```

#### 6. Query Data

**Python - Query by Expression:**
```python

results = collection.query(
    expr="year > 2020",
    output_fields=["id", "title", "year"],

```

**Python - Query by Primary Key:**
```python

```

#### Partitions

```python

collection.create_partition("tech_articles")
collection.create_partition("science_articles")

# Insert into partition

    param=search_params,
    limit=10,
    partition_names=["tech_articles"]

# Drop partition
collection.drop_partition("old_articles")
```

#### Time Travel

```python
import time

# Insert data
collection.insert(entities)
timestamp1 = int(time.time() * 1000)

# Modify data
collection.delete(expr="id < 100")
timestamp2 = int(time.time() * 1000)

# Query historical data
results = collection.query(
    expr="id < 100",
    travel_timestamp=timestamp1  # Query data as it was at timestamp1
)
```

### Integration Examples

#### With OpenAI Embeddings

```python
import openai
from pymilvus import Collection, connections

openai.api_key = "YOUR_OPENAI_KEY"
connections.connect(host='localhost', port='19530')

def get_embedding(text):
    response = openai.Embedding.create(
        input=text,
        model="text-embedding-ada-002"
    )
    return response['data'][0]['embedding']

# Store document
text = "Milvus is a vector database"
embedding = get_embedding(text)

collection = Collection("documents")
collection.insert([[1], [embedding], [text]])

# Search
query = "What is Milvus?"
query_embedding = get_embedding(query)

results = collection.search(
    data=[query_embedding],
    anns_field="embedding",
    param={"metric_type": "L2", "params": {"ef": 64}},
    limit=3,
    output_fields=["text"]
)
```

#### With LangChain

```python
from langchain.vectorstores import Milvus
from langchain.embeddings import OpenAIEmbeddings
from langchain.text_splitter import CharacterTextSplitter

# Initialize
embeddings = OpenAIEmbeddings()

# Create vector store
vector_store = Milvus(
    embedding_function=embeddings,
    collection_name="langchain_collection",
    connection_args={"host": "localhost", "port": "19530"}
)

# Add documents
texts = ["Document 1", "Document 2", "Document 3"]
vector_store.add_texts(texts)

```

## Best Practices

### Schema Design

- Use appropriate data types for scalar fields
- Set reasonable `max_length` for VARCHAR fields
- Use auto_id when possible to avoid ID collisions
- Plan partition strategy for large datasets

### Index Selection

- **Small datasets (<1M)**: FLAT for 100% recall
- **Medium datasets (1M-10M)**: IVF_FLAT or HNSW
- **Large datasets (>10M)**: IVF_PQ or DiskANN
- **Memory-constrained**: IVF_SQ8 or IVF_PQ

### Performance Optimization

- Batch insert data (1000-10000 per batch)
- Create appropriate indexes before loading
- Use partitions for data organization
- Configure `nprobe` / `ef` based on recall needs

### Resource Planning

- RAM: ~1.5x raw data size for in-memory indexes
- CPU: 8+ cores for production
- Disk: 3-5x raw data size for storage
- GPU: For large-scale, low-latency search

### High Availability

- Deploy cluster mode for production
- Use replicas for query nodes
- Configure persistent storage (S3/MinIO)
- Set up monitoring and alerting

## Troubleshooting

### Common Issues

**Connection Refused:**
```python
# Check Milvus is running
docker ps | grep milvus

# Verify ports
netstat -tulpn | grep 19530
```

**Out of Memory:**
```python
# Use disk-based index
index_params = {"index_type": "DiskANN", ...}

# Reduce cache size in config
# Edit milvus.yaml: cache.size
```

**Slow Search:**
```python
# Tune search parameters
search_params = {"nprobe": 10}  # Reduce for faster, less accurate search

# Add filters to reduce search space
expr="category == 'tech'"
```
